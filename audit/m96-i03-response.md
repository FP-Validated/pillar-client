## Departures from the recommendation

- **M-109.** Opt-in digest, not a single object or a version-pinned manifest. `quorum-strategy.json` is protected only if the rollout writes `_providersSha256`; without it the pair loads as before and one warning is logged. A deployment with `PROVIDER_CONFIG_TYPE=LOCAL` does not read two remote objects and is not affected.
- **I-03.** Documentation only. The 400 message is unchanged, so the observed per-provider depth is still the number in the body; SECURITY.md says it is one provider's observation. Reporting the caller's `blockConfirmation` and logging the depth was not done.
- **L-13.** The SSO bearer header is not redacted inside the SDK. The CLI log filter keeps `aws_smithy_runtime::client::orchestrator` at `info`, so the request dump is not printed.
- **L-16.** No monotonic clock. `elapsed_ms` returns the oldest possible age when the clock steps backwards, which is the recommendation's second option.
- **L-17.** The report asked for a per-packet or per-sender query; the Canton APIs cannot select one, so the response budget was raised to 16 MiB with the TON parse budget. Peak memory at that size has not been measured.
- **L-28.** The recursive matcher is replaced by augmenting paths. No separate cap on expanded category slots was added.
- **L-36.** The URI is dropped from the error. Scheme enforcement at configuration load and scheme-agnostic sanitizers were not added.
- **L-43.** A Stellar transaction without `events` is a provider failure naming `stellar-rpc` 23. The RPC version is not enforced by the health check and there is no `resultMetaXdr` fallback.
- **L-47.** Documented in SECURITY.md instead of projecting `sentEvent` onto upstream's key set; the recommendation allowed either.
- **M-101.** The TON account-state limit is 32 MiB; peak memory at that limit has not been measured (SECURITY.md says so).
- **L-42.** No code change: a TON v2 URL whose only parameter is `v3-endpoint` already has no query. The commit adds a test that pins it.
- **I-01.** No change: a missing, empty or unparseable TON principal is already refused (`observe_ton_transaction_from`).
